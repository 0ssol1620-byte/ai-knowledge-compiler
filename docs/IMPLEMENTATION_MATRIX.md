This matrix is a traceability record, not a production-readiness claim.
`IMPLEMENTED` means the chapter's deterministic local contract or artifact is
present and locally testable. It does **not** mean the whole SaaS is deployed.
`IMPLEMENTED-ADAPTER` means an interface, safe mock, feature-gated path, or
infrastructure scaffold exists, but production integration/evidence is absent.
`EXTERNAL-EVIDENCE-REQUIRED` means completion fundamentally depends on licensed
corpus data, real users/telemetry, provider accounts/GPU, current legal or
license review, payments, or production operations.

## Status definitions

| Status                       | Permitted claim                                                                             | Prohibited claim                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `IMPLEMENTED`                | Local contract/code/artifact exists and has a deterministic validation path.                | Deployed, production-approved, benchmark-winning, legally approved, or SLO-compliant without separate evidence. |
| `IMPLEMENTED-ADAPTER`        | Boundary/scaffold/mock is present and fails closed when production configuration is absent. | Provider/model/payment/storage/enterprise integration is operational.                                           |
| `EXTERNAL-EVIDENCE-REQUIRED` | Required evidence and acceptance criteria are identified.                                   | Complete, validated, best-in-class, profitable, compliant, or released.                                         |

Atomic requirement rows below use four additional labels:

| Atomic status    | Meaning                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `LOCAL-EVIDENCE` | Deterministic code or an artifact and a focused test/check path are present. This is not a claim that the check ran on the release commit. |
| `LOCAL-PARTIAL`  | A substantial local implementation exists, but one or more named contract details or deterministic checks are missing.                     |
| `LOCAL-GAP`      | The named behavior can be implemented or tested in this repository, but no adequate evidence was found.                                    |
| `EXTERNAL-GATE`  | Code alone cannot establish the requirement. The matching `EG-*` record in `docs/release/EXTERNAL_GATES.md` remains open.                  |

No `LOCAL-EVIDENCE` row closes an external gate. Conversely, an external
evidence bundle cannot waive a `LOCAL-GAP`.
