## The union maps to blueprint §11 field for field

Thirteen variants — `pdf`, `image`, `docx`, `xlsx`, `pptx`, `email`, `json`,
`xml`, `code`, `cad`, `media`, `database`, `api` — over the common base
(`locatorId`, `sourceVersionId`, `representationId`, `locatorKind`,
`contentDigest?`, `excerpt?`) plus `schemaVersion`. The Python transliteration
is snake_case; the wire is camelCase through `akc_cir.base.ContractModel`'s
alias generator, so the JSON a locator serializes to validates unchanged
against the frozen schema. A test asserts exactly that for one fixture per
variant, and asserts that ten malformed payloads are rejected by **both** the
frozen schema and the model.

Two deliberate asymmetries, both in the direction of stricter:

- The frozen schema has no `additionalProperties: false`; `ContractModel` has
  `extra="forbid"`. An unknown field passes the schema and fails the model.
- `BBox1000` (reused from `akc_cir.models`) enforces positive area, and
  `MediaLocator` enforces `startMs <= endMs`, mirroring what `SourceRef`
  already enforces for the same pair. The schema documents the first as
  "enforced by code, not expressible here" and says nothing about the second.

One asymmetry in the direction of looser, in the *generated TypeScript* only:
optional fields render as `T | null` because pydantic types them `T | None`.
The wire never carries `null` (`exclude_none=True` on serialization), and the
frozen schema does not permit it. A TS consumer should treat `null` as absent.

## `SourceRef` is not modified

Today's evidence type is `akc_cir.models.SourceRef`
(`packages/cir-python/src/akc_cir/models.py:73`), embedded **by value** in
`CanonicalBlock`, `CanonicalCell`, `CanonicalTable`,
`CanonicalKnowledgeObject` and three exporter models.
`CanonicalKnowledgeObject.hash` digests `source_refs` through `model_dump()`,
so any field added to `SourceRef` changes the hash preimage of every knowledge
object already stored. The union is therefore a **sibling type**, exactly as
§12 lists `evidence_locators[]` as its own array. Seam-map open decision O-2 is
resolved as "sibling" by contract §7 R-5, and the regenerated
`generated-contracts.ts` diff is additive only — every existing `SourceRef`
shape in it is byte-identical before and after.

The adapter is a pure round-trip:

```python
from_legacy(source_ref, *, representation_id, locator_id=None) -> PdfLocator
PdfLocator.to_legacy(*, document_id) -> SourceRef
```

`document_version_id -> sourceVersionId` is the identity alias this campaign
uses, mirroring the site's `sourceId = documents.id` (contract §7 R-8).
`page_number1 -> page`, `bbox1000 -> bbox1000`, `native_object_id -> objectId`.

`to_legacy` takes `document_id` as a parameter because the v2 union
deliberately carries no document id: a locator binds to a SourceVersion, and
the document → source alias lives on `Source`. This is the one place the
contract's `PdfLocator.to_legacy()` signature could not be met literally
without inventing a field the frozen schema does not have.

A `SourceRef` with `bbox1000 = None` **cannot** be wrapped: the frozen schema
requires `bbox1000` on the `pdf` variant, and `from_legacy` raises rather than
inventing a box. That is the fail-closed reading of "never invent data".

## Anchor identity

`identity.evidence_id()` is Protected Core and requires `page_number1 >= 1`, so
it structurally cannot express an XLSX cell or a JSON pointer. `identity.py` is
untouched. The non-paginated sibling is

```python
locator_anchor_id(locator) -> "sha256:<64hex>"
```

sha256 over the canonical JSON of the locator with `locatorId` and `excerpt`
removed. It is stable under renaming and re-excerpting, changes when the anchor
changes, and satisfies the schema's `Identifier` pattern, so it can be used as
the `locatorId` itself — which is what `from_legacy` does when none is supplied.

**Known risk, not solved here:** two anchor-id algorithms now exist (the
page-based `evidence_id`, the path-based `locator_anchor_id`). A source with
both a page-like unit and a native id needs one canonical convention before
anything indexes on either, or identity collisions become a real bug class.
That convention is a founder/architecture decision, not a lane decision.

## What the resolvers prove

`resolve_locator(locator, data) -> Resolved | Unresolved`. `Resolved` carries
`digest` (sha256 over the whole resolved unit) and `excerpt` (its first 2,000
characters, the schema's cap). `Unresolved` carries a frozen `FailureClass` and
a detail string. When the locator declares a `contentDigest` that disagrees
with what was actually read, the result is `Unresolved(RECEIPT_MISMATCH)` — a
locator that points at bytes that have changed is broken evidence.

Before this module, **nothing in the tree opened a representation and checked
that an anchor was really there**; only structural validation existed
(`page_index0 + 1 == page_number1`, bbox ordering). Seam-map contradiction C-5
called P0-E "a schema ticket wearing a resolution ticket's acceptance
criterion". These three resolvers are the answer to that half of it, on
committed fixtures only — no corpus, no calibration, no claim of coverage.

| Kind | What resolves | What it does not |
|---|---|---|
| `json` | RFC 6901 pointer, stdlib `json`. Escapes `~0`/`~1`; the empty pointer is the whole document; array indices reject leading zeros. Excerpt is the canonical JSON of the value. | Nothing deferred. JSONPath (§11 mentions both) is not implemented; the schema's field is `pointer`. |
| `xlsx` | Sheet by name → package relationship → worksheet part, through `zipfile` and `defusedxml`. Shared strings, inline strings, booleans, numbers and cached formula values. `cell` and `range` (row-major, tab/newline joined). | `namedRange`, `tableId`, `chartId` → `UNSUPPORTED_FORMAT`. The optional `workbook` field is **not** checked: the representation bytes are the workbook by contract, and there is no way here to bind an external workbook name to them. |
| `pdf` | Page-bound check against the real page count, then the page's native text via `pypdf`. | It resolves to the **page**, not to the bbox region. Nothing in this tree extracts text for an arbitrary rectangle; producing one would be a fabricated excerpt. `contentDigest` on a `pdf` locator therefore means "digest of the resolved page text". |

Guards, because a representation is hostile data: package parts over 8 MiB
declared size are refused (`CORRUPT_SOURCE`), ranges over 4,096 cells are
refused before expansion, XML goes through `defusedxml` (also what
`akc_native_parsers` uses — stdlib `xml.etree` would trip ruff `S314`), and an
encrypted PDF is `ENCRYPTED_SOURCE` rather than being misreported as corrupt.

`defusedxml` and `pypdf` are existing root dependencies; **no dependency was
added**.

## What is deferred

- **Ten variants have no resolver**: `image`, `docx`, `pptx`, `email`, `xml`,
  `code`, `cad`, `media`, `database`, `api`. They are typed, schema-validated
  and round-trippable, and `resolve_locator` returns
  `Unresolved(UNSUPPORTED_FORMAT)` for each — never a guess. Adding one is a
  new resolver class plus fixtures; the dispatch table is the only edit.
- **Region-level PDF resolution** (bbox → text) — see the table above.
- **The site-side serializer.** §48 P0-E lists a "UI serializer"; the seam map
  proposed `nextjs/lib/retrieval-units.ts`. Contract §7 R-5 defers it: that
  file hashes the whole unit into `contentDigest`, so adding a field re-hashes
  every stored retrieval unit. This lane is core-only.
- **`source_grounded_acceptance.py` still keys on an opaque
  `source_region_ref: str`.** Rewiring it to a structured locator is §20 work
  and is not folded in here. It is Protected-Core-adjacent and untouched.
- **`semantic_preservation.py` does not exist on this branch.** The contract's
  lane-E reading list names it; on `research/source-faithful-kc-v1` it is not
  present (it lives on `agent/tavonel-vkc-research`, which no lane touches).
  The nearest analogue that does exist is `source_grounded_acceptance.py`. No
  proposed diff against `semantic_preservation.py` is written here because the
  file could not be read.
- **Emission.** `ReaderProvider.emit_evidence_locators()` (lane C) is the
  producer; lane C validates locator dicts against the same frozen schema and
  does not import this module.
