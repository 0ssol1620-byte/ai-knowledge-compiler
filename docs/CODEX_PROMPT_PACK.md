# FOLYNTA Codex prompt pack

These short prompts preserve the repository authority order. They never replace
the root `AGENTS.md` or the active skill.

## Route implementation

> Read the root AGENTS, FOLYNTA brand skill, active PAGE_MANIFEST route, brand
> decisions, relevant masterplan section, and existing browser evidence. Define
> one route message, implement semantic static content first, add real
> interaction and source-linked data, then validate 1920, 1440, 1024, 390,
> reduced motion, keyboard, console, network, build, and Lighthouse. Do not add
> unregistered claims or generic AI decoration.

## Design engineering polish

> Inspect hierarchy, line length, spacing rhythm, borders, focus, targets,
> loading states, and motion. Keep marketing cinematic and product calm. Motion
> must explain a state change, remain interruptible, and preserve identical
> meaning with reduced motion.

## Asset production

> Read FOLYNTA Asset Director. Classify T0–T4, prefer actual product/public
> evidence, code/SVG, then first-party 3D. Never generate proof. Produce master,
> responsive derivatives, provenance, hashes, alt decision, in-context captures,
> byte budget, and an asset completion report.

## Browser QA

> Capture the route at 1920, 1440, 1024, and 390. Test default, reduced motion,
> keyboard, slow network, JavaScript failure/fallback where relevant, console,
> overflow, sticky layers, focus order, and content stress. Record critical/high
> findings, fix them, and recapture verified evidence.

## Final gate

> Do not call the route complete until traceability is current, all local
> validators pass, visual/a11y/performance thresholds pass, claim and asset
> manifests match hashes, PR CI is green, and owner-controlled blockers are
> explicitly separated from implementation work.
