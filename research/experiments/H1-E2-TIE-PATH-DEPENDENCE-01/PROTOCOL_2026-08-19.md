# H1-E2 — tie-permutation path dependence and promotion veto

Frozen 2026-08-19 **after** H1-E observed eight residual `OTHER` divergences and **before** any H1-E2 future-state result is produced.

This is a follow-on protocol. It does not change H1-E's frozen criteria, does not re-open the Family B fresh-seed holdout, and does not convert H1-E's controlled evidence into real-corpus evidence.

## Question

H1-E found `FAIL_OPEN = 0` and `FAIL_CLOSED = 0`, but eight row-attached decisions differed in the `split_and_merge` topology. The outcome multiset was the same while the source positions receiving `NEW` versus `AMBIGUOUS` changed.

The protected-core question is narrower and stricter:

> Are those row permutations observationally invariant once the decision attached to each source position is allowed to become the prior identity state for a later revision?

A multiset equality is **not** sufficient. Stable identity is consumed by temporal history, dependency traversal, lineage and recompilation by logical ID, so the row attachment is part of the semantics.

## Frozen source

The `freeze` phase mechanically selects the H1-E equivalence receipt that:

1. has a recomputable receipt self-hash;
2. pins the live `akc_cir.identity` bytes;
3. records `FAIL_OPEN = 0`, `FAIL_CLOSED = 0`, `OTHER = 8`;
4. uses the frozen H1-E seed and generated `split_and_merge` cell.

The seal records that receipt's path and byte hash plus the hashes of this protocol, this runner, the H1-E runner, and the live identity module. The `run` phase refuses drift. The seal is written before the result.

## Current-state reconstruction

For each of the 60 original `split_and_merge` cases at 80 source units, recreate the exact H1-E inputs from seed `20260819` and recompute LEGACY and BLOCKED decisions against the sealed identity implementation.

Only rows whose full H1-E decision key differs are primary probe rows. A policy's next prior-state contains each current source fingerprint for which that policy emitted a non-null `logical_id`, with the fingerprint's `logical_id` replaced by the decision's logical ID. An `AMBIGUOUS` decision contributes no asserted continuity; inventing one would erase the very abstention being tested.

## Next-revision probe

For every divergent source row, construct the **same** next-version fingerprint for both arms by preserving its normalized text, path, anchors, lineage and other identity signals while assigning a fresh seed logical ID. Resolve that one future row against the LEGACY-derived prior-state and, separately, the BLOCKED-derived prior-state using the same `MatchingPolicy.LEGACY` resolver in both arms.

Using LEGACY for both future probes isolates path dependence created by the current-state difference; it does not compound the test with another BLOCKED approximation.

Compare future decisions on the full H1-E key:

`(match, logical_id, relation, sorted(candidates))`.

## Controls / falsification

Two controls are mandatory.

- **Negative deterministic control:** the same future probe against two byte-equivalent copies of the same prior-state must yield zero divergences.
- **Positive continuity-removal arm:** an exact prior fingerprint is present in one arm and absent in the other. The future decision comparator must separate. If it does not, the harness is invalid and no promotion statement is allowed.

The old outcome-multiset comparison is reported only as a diagnostic and never as an acceptance rule.

## Frozen decision rule

`BLOCKED` remains shadow unless **all** of the following are true:

1. the positive falsification arm separates;
2. the negative control has zero divergence;
3. every row-attached H1-E divergence has zero next-revision decision divergence under this protocol.

If even one valid next-revision probe differs, disposition is:

`PROMOTION_VETO_PATH_DEPENDENT`.

That result does **not** invalidate H1-E's measured speed/memory benefit. It means the current BLOCKED tie semantics are not an exact protected-core replacement for LEGACY. A later implementation may change tie-breaking under a new protocol, but the present result may not be waived post hoc.

## Evidence class and allowed wording

Evidence class: **controlled generated mechanism evidence**.

Allowed if vetoed:

> The sparse/component matcher removed the measured scalability bottleneck in shadow tests, but residual tie assignments were path-dependent across revisions, so it was not promoted as the default identity policy.

Forbidden:

- “the residual permutations are harmless because their multiset is identical”;
- “BLOCKED is equivalent to LEGACY” if this protocol observes any future divergence;
- any external/generalization claim from this experiment.
