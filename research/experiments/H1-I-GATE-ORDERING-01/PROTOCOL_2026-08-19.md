# H1-I — Is the promotion gate's check *ordering* load-bearing?

**Frozen 2026-08-19, before any permutation was executed and before any result
was inspected.** Written because `docs/audit/ABLATION_COVERAGE_2026-08-19.md`
§2.1 recorded that claim B1 element 7 recites the order of the four gate checks
as a limitation, and that nothing measures it.

---

## 1. The question

Claim B1 element 7 recites "an ordered sequence of checks"; element 9 permits
activation "only if **every** check in element 7 passes".

> Does the order in which the four checks are evaluated change whether a
> candidate knowledge state is admitted?

## 2. The a-priori answer, stated before running so it cannot be claimed after

Element 9 is a conjunction. A conjunction is commutative, so on any state where
all four checks are evaluated, order **cannot** change the admit/refuse verdict.
**A null result on the primary endpoint is therefore expected**, and this
protocol is written to make that null actionable rather than embarrassing.

The reason to run it anyway is that the implementation *short-circuits*
(`skip_rest`), so the four checks are not all evaluated on every state, and
short-circuiting is where an ordering effect could hide. Reasoning does not
settle whether it does. That is the measurement.

## 3. Endpoints

**E1 — primary.** Over the frozen state set, does any permutation of the four
checks change the binary verdict (`promotable` true/false)?

*Falsification:* E1 is falsified — i.e. ordering IS load-bearing for the verdict
— if at least one (state, permutation) pair yields a verdict different from the
canonical order's verdict on that same state.

**E2 — secondary.** Does permutation change (a) which check is reported as the
cause of refusal, and (b) whether a check is evaluated on input another check
would have rejected first?

E2 exists because "order does not change the verdict" and "order does not matter"
are different statements, and only the first is what E1 can show.

## 4. The narrowing rule — binding, frozen before results

**If E1 returns null (no permutation changes any verdict), claim B1 element 7's
recitation of order is NOT supported as affecting the admitted/refused outcome,
and the claim must be narrowed accordingly** — the order is retained in the
specification as an implementation property and, if E2 is positive, defended as
*diagnostic attribution and evaluation soundness* rather than as outcome
control. Counsel is to be told this in the same sentence as the result.

Defending the ordering limitation on the strength of a null is prohibited by
this protocol. Accepting this outcome in advance is what makes this an
experiment rather than a demonstration.

## 5. State set — constructed and frozen before execution

Six candidate states, each built to sit at a distinct point in the gate's
decision space. The set deliberately includes the case the audit named:
**internally consistent AND incomplete** (S3), which is where an ordering effect
would appear if one exists anywhere.

| id | construction | intent |
|---|---|---|
| S0 | all checks satisfiable | the only admissible state; verdict must be PASS |
| S1 | a change names a unit absent from the graph | fails check 1 only |
| S2 | affected artifact not rebuilt | fails check 2 only |
| S3 | rebuild incomplete **and** every fingerprint present and matching | consistent-but-incomplete: fails 2, would pass 3 |
| S4 | carried-forward artifact whose input fingerprint disagrees | fails 3 only |
| S5 | structural-dependency artifact without declared structural coverage | unverifiable, fails 4 only |

Multi-failure states are not added: a state failing two checks is refused under
every order trivially, and adding them would inflate the denominator without
adding discriminating power. Stated here so the omission is a design decision on
the record and not a gap discovered later.

## 6. Method, and the guard against measuring the harness

`evaluate_promotion_gate` has a fixed order and is **Protected Core — it is not
modified for this experiment.** The harness therefore implements the four checks
as independent predicates that can be sequenced arbitrarily.

**Fidelity gate, binding:** for every state in §5, the harness run in the
canonical order must reproduce `evaluate_promotion_gate`'s verdict *and* its
first failing step. **If fidelity fails on any state, the experiment is void and
reports no ordering result** — a permutation study over a harness that does not
reproduce the system measures the harness. This is the same failure mode that
invalidated W6 v1 and it is gated the same way.

All 24 permutations (4!) x 6 states = 144 evaluations. Deterministic, CPU-local,
no network, no GPU, $0.

## 7. Stop rule

One execution. Results are not re-run, and the state set is not extended after
results are seen. If the fidelity gate voids the run, the harness is corrected
and the correction is recorded as a superseded attempt in the ledger — the
protocol itself is not amended to fit.
