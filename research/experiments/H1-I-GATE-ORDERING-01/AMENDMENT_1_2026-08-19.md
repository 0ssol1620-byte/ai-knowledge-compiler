# H1-I Amendment 1 — the permutation arm could not separate

**Raised after seeing attempt 2's null and before citing it anywhere.** The
protocol is not being changed to fit a result; an arm that cannot produce the
outcome it is supposed to detect is being labelled as such, and a control is
being added to establish whether the instrument works at all.

## What the null actually showed

Attempt 2 passed the fidelity gate and returned E1 = 0 verdict divergences and
E2 = 0 cause divergences over 144 evaluations. Read naively that is "ordering
does not matter". It is not evidence for that.

**The four checks are implemented as pure functions of the candidate state.**
None consumes another's output. Under that structure:

- no permutation can change any individual check's value;
- the verdict is their conjunction, and conjunction is commutative;
- so E1 is **incapable of returning a divergence**, whatever the truth is.

E2's cause endpoint fails the same way for a second reason: §5 deliberately
constructed each state to fail exactly one check, and with one failing check the
first-failing step is that check under every order.

This is the identical defect the programme already recorded once, in
`H1-E-IDENTITY-SCALABILITY-01`: a falsification arm whose weakening could not
change any answer by construction. A zero from it tested nothing. The rule
applied there applies here.

## Amendment

Add a **positive control** — a deliberately order-dependent variant of the four
checks in which `INTEGRITY` reports a pass when the completeness check has not
yet run, and a fail when it has. This variant is not the system and is never
promoted as evidence about the system. Its only job is to answer:

> Given a gate whose ordering genuinely is load-bearing, does this harness
> detect it?

**Binding interpretation, frozen now:**

- If the positive control shows **no** divergence, the harness is a broken
  instrument, the ordering question remains **unmeasured**, and the null from
  attempt 2 may not be cited for any purpose.
- If the positive control **does** diverge, the harness separates, and attempt
  2's null becomes meaningful evidence for the narrow proposition that *the
  four checks as implemented are mutually independent, and therefore ordering
  cannot affect the verdict.*

Note what the second branch does and does not license. It supports "order is not
load-bearing **because the checks are independent**". It does not license
"ordering is unimportant in general" — a gate whose checks consumed one
another's output would be a different system, and this result says nothing about
that one.

## Effect on the §4 narrowing rule

Unchanged and still binding. On the second branch the E1 null stands, and claim
B1 element 7's recitation of order must be narrowed accordingly.
