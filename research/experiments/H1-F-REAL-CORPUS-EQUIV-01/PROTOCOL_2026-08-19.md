# H1-F — all-stored natural-revision selective/full equivalence regression

Frozen 2026-08-19 before H1-F endpoint execution.

## Purpose

Close the specific hostile-review gap that the current Family B evidence package lacks a **live-code-pinned real-corpus equivalence arm**.

This is **not** a fresh holdout and **not** confirmatory evidence. The source revisions were acquired and used by earlier development/confirmatory/extension work. H1-F is deliberately classified as:

`REAL_CORPUS_EMPIRICAL / retrospective all-stored regression`.

It may establish that the current implementation reproduces selective-vs-full equivalence on the natural revision data already stored in the repository. It may not establish general equivalence or external validity beyond this corpus family.

## Frozen corpus rule

No title is selected from outcomes. The corpus is the complete set of leaf directories containing exactly two `.wikitext` files under all three already-existing Family B stores:

- `H1-B-REAL-REVISION-01/corpus`
- `H1-B-REAL-REVISION-01/corpus-confirmatory-v1`
- `H1-B-REAL-REVISION-01/corpus-extension-v1`

At freeze time this rule yields **28 natural revision pairs / 56 source files**. The seal records every relative path and SHA-256. Any later corpus byte or membership drift aborts the run.

The two files in each leaf are ordered by numeric MediaWiki revision id from the filename; lower id is before, higher id is after. No network access is permitted during H1-F.

## Adapter and implementation pins

The run reuses the existing Wikipedia semantic-section projection and `run_pair` logic from `run_public_real_revision_holdout_v3.py`, but reads only the sealed local corpus.

The seal pins:

- this protocol;
- this runner;
- the reused v3 adapter runner;
- live `identity.py`;
- live `semantic_diff.py`;
- live `dependency.py`;
- live `recompilation.py`;
- all 56 source files.

The run refuses drift rather than editing receipts.

## Endpoint

For every natural revision pair:

1. derive semantic section units and document shape;
2. compute current semantic diff;
3. construct the existing typed artifact dependency graph;
4. plan selective recompilation;
5. compute a full-rebuild oracle;
6. carry only artifacts classified CURRENT;
7. compare selective+carried state with the full rebuild using `verify_equivalence`.

Primary descriptive endpoints:

- pair count;
- changed-pair count;
- equivalent-pair count;
- stale-left-behind total;
- total artifacts and rebuilt artifacts;
- rebuild fraction distribution.

The success condition for the **regression statement only** is all 28 pairs equivalent with zero stale artifacts. Failure is retained and narrows the claim.

## Evidence boundaries

Allowed on success:

> On all 28 previously acquired natural English-Wikipedia revision pairs stored across the Family B development/confirmatory/extension corpora, the live pinned implementation's selective result matched its full-rebuild oracle with no stale artifact left behind.

Required limitation:

> The corpus is retrospective, English Wikipedia only, and its artifact graph is an evaluation adapter rather than an unconstrained production dependency graph; this is real-corpus regression evidence, not proof of general equivalence.

Forbidden:

- “Family B is generally equivalent to full rebuild.”
- “External validity is proven.”
- “28 independent domains were tested.”
- calling H1-F a fresh holdout or confirmatory endpoint.
