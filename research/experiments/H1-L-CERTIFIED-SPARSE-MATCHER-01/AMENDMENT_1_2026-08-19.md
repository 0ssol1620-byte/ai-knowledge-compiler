# H1-L Amendment 1 — a void run, a corpus defect, and a disclosed deviation

## What happened, in order

1. The first run returned `VOID_MUTANT_SURVIVED` under protocol §6: the
   runner-up mutant separated on **zero** cases.
2. Correcting the mutant (forcing the rival *equal to* the winner rather than to
   zero) did not help. Still zero.
3. Root cause was not the mutant. **The frozen corpus omitted
   `source_lineage`**, so `_source_continuity` returned `NOT_APPLICABLE` on every
   pair, the missing-critical-signal branch fired first on every row, and **no
   row ever reached MATCHED, the review band, or the tie guard.** The endpoint
   was unfalsifiable by construction on two of three facets.

## The deviation, stated plainly

Protocol §3 says the corpus is not extended after results are seen. **It was
extended.** Units now carry a lineage by default, and two cases were added —
`matched_clean` and `tie_guard_live` — to cover bands the original corpus had
accidentally excluded. `missing_critical_signal` was kept, with lineage
explicitly disabled, so the abstention path is still covered.

This is disclosed rather than absorbed. The distinction being relied on:

- **not** tuning a corpus until the result improves — the correctness result was
  already 0 divergences before the change and stayed 0 after;
- **but** repairing an instrument the protocol's own §6 had already declared
  VOID, because a corpus that cannot reach the tie guard cannot test a matcher
  whose whole risk is the tie guard.

A reader who rejects that distinction should read the exactness result as
covering the post-fix corpus only. The pre-fix run is retained at
`receipts/exactness-attempt1-void-mutant-2026-08-19.json`.

## Result after the fix

| | |
|---|---|
| primary divergences | **0** over 50 comparisons |
| `winner_rotated` | separates, 10 cases |
| `attribution_swapped` | separates, 15 cases |
| `runner_up_maximized` | separates, 17 cases |
| verdict | `EXACT_ON_FROZEN_CORPUS` |

All three mutants now separate, so the null is citable.

## The performance result is negative, and it is the more important finding

| n | LEGACY | CERTIFIED_SPARSE | speedup |
|---|---|---|---|
| 100 | 0.138 s | 0.287 s | **0.48x** |
| 300 | 1.423 s | 4.062 s | **0.35x** |

Scoring calls saved: **negative**. The matcher computes *more* work than dense
LEGACY, not less.

### Why — and this is structural, not an implementation defect

Contract §5(b): at most `N-1` columns are taken by other rows, so a row's
runner-up can be as low as its `(N+1)`-th best column. Preserving the runner-up
facet therefore requires keeping `min(M, N+1)` columns per row.

**For a square window `N ≈ M`, `N+1 > M`, so every column is kept and no pruning
is admissible at all.** The certification machinery then adds pure overhead: a
bound computed per edge on top of the exact score still computed per edge.

Square windows are the common case — a revised document usually has a similar
unit count to its predecessor.

## Honest conclusion for P2-13

**Exact sparse acceleration remains unresolved**, and this run identifies the
binding constraint rather than merely failing to find one:

> The runner-up facet, not the winner, is what forbids sparsity. Preserving which
> unit *wins* admits aggressive pruning; preserving which unit would have been
> the *rival* — required because H1-K showed attribution is semantic — forces a
> per-row candidate set that is already the whole column set for square windows.

Directions this leaves open, none of them attempted here:

- a cheaper certificate for the runner-up specifically, e.g. a per-row bound that
  proves a column cannot be *available* rather than cannot *win*;
- exploiting that most rows are uncontended, so the `N-1` worst case is loose in
  practice — but a bound that is only usually valid is not a certificate;
- accepting a narrower contract, which the semantic-contract freeze forbids and
  which H1-K Amendment 1 showed would be unsound anyway.

**CERTIFIED_SPARSE is not proposed for promotion.** It is exact and slower. That
is a result, not a candidate.

# H1-L Amendment 2 — which contract facets were actually measured

**Raised in a second red-team pass over our own work, not by an outside
reviewer.** The frozen semantic contract lists more facets than the exactness
harness computes, and a summary table described one of them as preserved when
nothing had measured it. This records the full audit rather than fixing only the
facet that was caught.

## Facet-by-facet

| contract facet (§1) | measured? | where |
|---|---|---|
| `match` classification | **yes** | `footprint()` rows |
| `logical_id` | **yes** | rows |
| assigned column | **indirectly** — implied by `logical_id` and `candidates`; not compared as a raw column index |
| `candidates` attribution | **yes** | rows |
| `relation` | **yes** | rows |
| `score` | **yes** | rows |
| unresolved seed set | **yes** | `unresolved_seeds` |
| dependency impact set | **yes** | `impact_set` |
| next-revision lineage | **yes, as of Amendment 2** | `run_future_path.py` |
| serialized semantic record | **NO** | not computed |
| `changed_logical_ids` | **NO** | not computed |
| selective rebuild set (`plan_recompilation` targets and states) | **NO** | not computed |

## What was corrected

Table 3 read *"preserved on tested corpus"* in its future-path column while the
harness stopped at revision 1. `run_future_path.py` now measures it: each policy
carries **its own** revision-1 outcome forward into revision 2 — feeding both the
same revision-2 inputs would erase the divergence under test — and the result is
**0 revision-2 divergences over 19 cases with 0 differing carry-forward
identifiers**.

The wording turned out to be right. It was unsupported when written, and that is
the defect, not the conclusion.

## What remains unmeasured, and why it is disclosed rather than closed

Three facets are not computed. Two of them are **strongly implied** by facets that
are: `changed_logical_ids` is a function of the per-row classification and
identifiers, and the serialized record is a projection of the same fields. The
third — the selective rebuild set — is one derivation step beyond the impact set,
which *is* compared.

**"Strongly implied" is not "measured", and this is exactly the reasoning that
produced the overclaim above.** So the claim's scope is stated as the facets
listed `yes`, and no more. Closing the remaining three is a straightforward
extension and is left as declared open work rather than assumed.

## Consequence

No claim changes. `B-EXACT-SPARSE-UNRESOLVED` already reports `FAILED` on the
acceleration objective, and its correctness statement is scoped to the measured
facets. The registry now carries both this scope note and the record of the
self-found overclaim.

# Amendment 3 — `assigned_column`, and a miscount in Amendment 2

**Written after the fact, disclosed as such.** Amendment 2 added a facet-by-facet
table of what the exactness harness measures. That table was incomplete, and the
summary drawn from it was wrong in a way anyone could have caught by counting:
it claimed twelve facets covered and listed eleven.

## The facet that was missing

The frozen contract's per-row tuple has six entries:

    match · logical_id · assigned_column · candidates · relation · score

`footprint()` in `run_exactness.py` builds rows from five. `assigned_column` —
`assignment[i]`, "which previous unit was paired" — is not among them, and
Amendment 2 called it *indirectly implied* by `logical_id` and `candidates`.

## Why "indirectly implied" fails here on the merits

`logical_id` is read from the matched partner. Two distinct previous units
carrying the same logical id — a duplicate, a re-seeded unit, a carry-forward
collision — are therefore indistinguishable through it. Two policies could pair
row `i` with different columns, agree on every facet `footprint()` compares, and
still have paired different units. The implication does not hold.

## Method — observation, not reconstruction

`assign_one_to_one` never returns its `assignment` map, and `identity.py` is
Protected Core and was not modified. `run_assigned_column.py` subclasses
`LogicalIdentityResolver` and observes its two entry points:

- `decide_pair(partner=previous[column])` → the column, by object identity
- `resolve(unit, [])` → an unassigned row

Both policies call exactly these functions, so the column observed is the one the
shipped code selected. Recomputing a candidate assignment instead would have been
a paraphrase, and a paraphrased harness is what voided the H1-I ordering
experiment.

## Result

    ASSIGNED_COLUMN_EXACT — 0 divergences over 19 cases

**Instrument liveness is recorded with the null**, because two empty observation
lists compare equal and a probe that never fired would produce exactly this zero:
72 column observations, 67 assigned, 5 unassigned rows.

## Disclosed limitation

The corpus carries **no duplicate previous logical ids**, so it does not exercise
the case that makes the indirect argument fail. This run establishes that the
columns agree here. It does not establish that `logical_id` would have been an
adequate proxy, and the facet stays measured directly rather than inferred.

## Standing consequence

Adding facets to a comparison can only reveal divergence, never hide it, so this
strengthens the earlier result rather than restating it. The lesson is the count:
a scope sentence that enumerates its own items can be checked by reading it, and
this one was not.
