# H1-L — CERTIFIED_SPARSE exactness protocol

**Frozen 2026-08-19, before the matcher was run and before any result was seen.**
Semantic contract: `SEMANTIC_CONTRACT_2026-08-19.md`, frozen first.

`MatchingPolicy.BLOCKED` is untouched and stays under the H1-E2 veto. This is a
separate policy with a separate experiment id, as P2-13 §4.3 requires.

## 1. Primary endpoint — correctness, gating

Zero divergences on the frozen contract footprint, compared **row-attached and
ordered**, never as a multiset:

- `match`, `logical_id`, `candidates`, `relation`, `score` per row
- unresolved seed set
- dependency impact set derived from those seeds

**`candidates` is in the primary endpoint**, per H1-K Amendment 1's CASE_B
finding. Excluding it would be excluding a field that changes the rebuild set.

## 2. Success rule

- **any primary divergence -> PROMOTION VETO.** No speedup justifies one.
- exact but not faster -> a scientific result, reported as such.
- exact and faster -> promotion *candidate* only; promotion needs a separate
  decision this protocol does not make.

## 3. Stop rule

One execution over the frozen corpus. Corpus is not extended, trimmed or edited
after results are seen. A harness defect is corrected and the defective run is
retained as a superseded receipt; the protocol is not amended to fit.

## 4. Performance is secondary and is only reported if §1 passes

Scoring calls saved, certification rounds, fallback rate, wall time at n=100 and
n=300, against the LEGACY baseline. No success threshold is set on speed. "Must
beat 46x" is explicitly not a criterion.

## 5. Frozen corpus

ordinary · equal_score_tie · split · merge · split_and_merge ·
identical_candidates · contended_column · rows_gt_cols · cols_gt_rows ·
all_equal_scores · threshold_adjacent · missing_critical_signal ·
runner_up_sensitive · low_score_but_semantic · dependency_separated ·
scale_12 · scale_30

Each is additionally run under candidate-order permutations and incoming-row
permutations, because H1-K showed attribution is order-sensitive.

**Known gap, declared now rather than discovered later:** the H1-E residual 8
cases are *not* included. They live in the H1-E harness against a generated
corpus this experiment does not load, and wiring them in is a separate task. This
protocol therefore cannot claim coverage of them, and the result must say so.

## 6. Positive falsification — mandatory

Three mutants, each corrupting one facet the endpoint is supposed to protect:

| mutant | corrupts |
|---|---|
| `winner_rotated` | the assigned partner |
| `attribution_swapped` | only `candidates`, leaving match and logical_id intact |
| `runner_up_zeroed` | the tie guard's runner-up |

**Every mutant must be caught. If any survives, the run is VOID** and reports no
exactness result — the same rule H1-I Amendment 1 established after a
non-separating arm nearly produced a citable null.

`attribution_swapped` is the important one: it is the mutant a
classification-only endpoint would miss, and it is present precisely because the
endpoint was widened.

## 7. Null interpretation

Zero divergences means *exact on this corpus under these perturbations*. It does
not mean proven exact in general. The certificate argument in the contract §6 is
what would generalise it, and it is an argument, not a measurement.
