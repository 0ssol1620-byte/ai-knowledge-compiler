# H1-K Amendment 1 — `candidates` is semantic, and the proposed endpoint is withdrawn

**Raised before the P2-13 endpoint was frozen, which is the only reason it is
cheap.** The extraction document proposed treating the reported candidate/tie
attribution as a *secondary* endpoint, on the grounds that LEGACY does not define
it stably under exact ties. That proposal is **withdrawn**.

Evidence: `receipts/candidates-semanticity-audit-2026-08-19.json`.

---

## The error in the proposal

"The implementation does not define this stably" and "this is not part of the
contract" are different statements. Only the second would license dropping a
field from an exactness endpoint, and the extraction document reasoned from the
first to the second without checking. An implementation artifact that is
persisted and read downstream **is** a contract.

## What the audit found — CASE B

`LogicalIdentityDecision.candidates` is not diagnostic. It flows:

    identity decision.candidates
      -> SemanticChange(kind=IDENTITY_UNRESOLVED, candidates=...)   semantic_diff.py:568
      -> recompilation unresolved_seeds                             recompilation.py:253
      -> promotion gate changes-accounted impact seeds              promotion_gate.py:224
      -> SemanticChange.as_record()["candidates"]                   semantic_diff.py:254-255

So the attribution seeds the **selective-recompilation traversal**, seeds the
**promotion gate's first check**, and is **serialized into the diff record**.

### The dynamic probe, which is the part that settles it

Same logical problem, `previous` list permuted, with `u1` and `u2` given
different dependents so the probe can separate:

| candidate order | `candidates` | impacted artifacts |
|---|---|---|
| `[0, 1]` | `['u1']` | `artifact:from_u1` |
| `[1, 0]` | `['u2']` | `artifact:from_u2` |

**A different candidate-list order produces a different rebuild set and a
different serialized record.** That is an externally observable artifact
difference, not a cosmetic one.

## Which branch fires, exactly

In the probed case the AMBIGUOUS comes from the **missing-critical-signal**
branch (`source_continuity` absent), which returns `candidates=(best,)` — a
single unit. Which unit is `best` among exact ties comes from the Hungarian
assignment, hence the order dependence.

**Known open refinement, stated rather than glossed:** the *tie-guard* branch
returns `candidates=(best, runner_up)` — both units. Permuting there may change
only the tuple *order*, which would still change the serialized record and any
hash over it, but might leave the seed *set* and therefore the traversal
unchanged. That branch was not separately probed. The CASE B verdict does not
depend on it, but the precise blast radius per branch does.

## Endpoint decision — binding for the P2-13 protocol

**Candidate attribution is part of the exactness endpoint.** A replacement
matcher must reproduce it, not merely reproduce classification and logical id.

Primary correctness endpoint for the eventual frozen protocol:

- classification
- logical id
- **candidate attribution** (added by this amendment)
- row attachment
- future lineage/path
- downstream impact / rebuild set

## A distinction this amendment also fixes

The extraction document should not be read as claiming LEGACY is
nondeterministic. Two separate statements:

- **The problem specification does not define a unique optimum.** Multiple
  equal-weight assignments exist and no semantic tie rule selects among them.
  True.
- **The implementation is nondeterministic.** **False**, and not claimed. The
  repeat-determinism probe HOLDS: the same input yields the same output every
  time. Iteration order and zero-padding select one optimum *repeatably*.

Whether that repeatable selection is a public contract or an implementation
artifact was the open question. **This audit answers it: it is observable
through the rebuild set and the serialized record, so it is a contract.**

## Consequence for P2-13 feasibility

Harder than the extraction document implied. A replacement must preserve not
only which units continue which, but which unit is *named* when identity is
unsettled — a value currently determined by Hungarian iteration order over the
caller's list order. Any pruning that changes candidate enumeration order can
change it.

This does not close P2-13. It rules out one class of shortcut and says so before
a protocol was frozen around it.
