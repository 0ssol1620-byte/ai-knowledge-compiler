# W6 v2 — frozen before the question set was built

`PATENT_FILING = NOT FILED`. `PAPER_SUBMISSION = NOT SUBMITTED`.

v1's question set is INVALID/SUPERSEDED
(`receipts/question-set-v1-invalidation-2026-08-19.json`): all eight criteria
passed while median query↔oracle token overlap was 1.0. Everything below is
fixed before a single v2 question exists.

---

## 1. Question classes and minimum samples

| class | n (min) | role |
|---|---|---|
| simple retrieval | 40 | **control only.** All arms expected to pass; not evidence |
| **revision-sensitive** | **60** | **primary endpoint** |
| conflicting evidence | 30 | included *only if real conflicts exist*; see §3 |
| multi-document | 30 | answer must require ≥ 2 sources |
| provenance-sensitive | 40 | exact evidence location is gold, not just the answer |

A class that cannot reach its minimum from real data is reported as **NOT
RUN — insufficient real cases**, never padded and never simulated.

## 2. Question-generation rule — intent comes from outside the passage

v1 failed because queries were built from the target's own wording. In v2 a
question is generated from a **structured fact tuple** extracted from the
document — `(subject, attribute, value, revision, unit_id)` — and rendered
through a fixed template that uses *only* the subject and attribute. The value,
and the sentence carrying it, never enter the query.

Templates are fixed here: `"What is the {attribute} of {subject}?"`,
`"As of {date}, what is the {attribute} of {subject}?"`,
`"Which source states the {attribute} of {subject}, and where?"`.

## 3. Leakage metric and acceptance

- **Median query↔oracle content-token overlap ≤ 0.50**, and
- **90th percentile ≤ 0.75**, and
- zero verbatim substring containment.

Overlap is now a frozen criterion rather than a diagnostic. A question set
breaching it is discarded before any arm runs.

**Conflicting evidence:** used only where two units genuinely assert different
values for the same `(subject, attribute)` in overlapping validity. If the corpus
yields none — which W5 found for a linear revision chain — the class is reported
as NOT RUN. Manufacturing a conflict to score conflict-handling is forbidden.

## 4. Candidate pool

Every unit of every document, **both revisions indexed** for the RAG arm — with
revision provenance withheld from the arm, which is exactly the disadvantage
under test. v1 indexed only the before-revision to prevent leakage; v2 must
instead make the temporal ambiguity real, since that is the phenomenon.

Distractor competitiveness is measured, not assumed: the score gap between the
oracle and the strongest non-oracle candidate must have a median **> 0** and a
25th percentile **< 3×** the median, so the task is neither trivial nor
degenerate.

## 5. Baseline validity gate — re-run before any arm

| criterion | threshold |
|---|---|
| Recall@1 | **0.30 – 0.90** (both bounds binding) |
| Recall@5 | 0.60 – 0.98 |
| exact-tie rate | ≤ 0.05 |
| median query↔oracle overlap | ≤ 0.50 |
| p90 overlap | ≤ 0.75 |
| same-document top-1 share | ≤ 0.80 |
| candidate-set entropy (top-10 score distribution) | ≥ 1.5 bits |
| revision leakage: queries naming a revision id or date present only in one revision | 0 |

**Upper bounds are as binding as lower bounds.** v1 taught that a ceiling is a
failure; it is now a failure by rule.

## 6. Arms

`RAW` (whole documents, no retrieval) · `BASIC RAG` (BM25 top-k over both
revisions) · `TAVONEL` (compiled world with identity, valid-time and provenance).
Same frozen model, same decoding parameters, same question set, same top-k.

## 7. Endpoints

**Primary:** answer correctness on revision-sensitive questions.
**Primary comparison:** TAVONEL vs BASIC RAG. RAW is a floor, not the comparator.

**Secondary (Holm-corrected, 7):** stale-answer rate · temporal correctness ·
evidence correctness · provenance localization · unsupported assertion rate ·
conflict handling · appropriate abstention.

## 8. Statistics

Paired by question — every question goes to all three arms. **McNemar** for
binary outcomes on the primary; exact test where counts are small. Per-class
results reported separately; **no aggregate mean across classes**, which would
hide which problem class a compiled world actually helps with.

## 9. Exclusion and abstention

- **Exclusion:** a question is excluded only if its gold answer cannot be
  established from the frozen text, and only *before* any arm is scored.
  Post-hoc exclusion of questions an arm got wrong is forbidden.
- **Abstention scoring:** abstaining on an answerable question counts as wrong.
  Abstaining where the evidence genuinely does not determine an answer counts as
  **correct**. Confidently answering the latter counts as an unsupported
  assertion. An arm cannot win by refusing to answer, and cannot win by guessing.

## 10. No post-hoc tuning

Prompt, retrieval, top-k and questions are frozen at §1–§6. If any needs changing
after results are seen, **that run is sealed as development** and a new untouched
holdout question set is required. This is the same rule that kept the B-EQUIV
fresh-seed holdout unspent.
