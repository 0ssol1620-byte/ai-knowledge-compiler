# H1-J — per-filter governance ablation

**Frozen 2026-08-19, before any filter was disabled and before any result was
inspected.** Closes the second and last gap in
`docs/audit/ABLATION_COVERAGE_2026-08-19.md` §2.2, which recorded that
`D-GOVERNANCE-LINEAGE-CONTROLLED` shows 22 cells passing with every filter
enabled and shows nothing about what happens when one is removed.

---

## 1. The question, and the question it is *not*

> For each governance filter: does removing it let a violation through?

Not "how many cases still pass". A per-filter pass/fail count is the wrong
instrument, because this system has **deliberate redundancy** — see §3 — and a
redundant filter produces a null that looks exactly like an inert one.

## 3. The redundancy that makes a naive ablation useless

**R1, R2 and R3 restate F1, F2 and F3.** A claim that fails the permission
filter also scores 0 at ranking position 1. So disabling F1 alone will usually
change nothing: the offending claim is admitted but ranks below any compliant
claim, and the answer is unchanged.

That null would mean "F1 is redundant *here*", not "F1 is unnecessary".

**The mask breaks when no compliant alternative exists.** With only violating
candidates present, the ranking element has nothing to rank them below, and the
missing admissibility filter is the only thing that could have refused. Every
filter is therefore tested under two states:

- **paired** — a violating claim *and* a compliant alternative;
- **solitary** — the violating claim only.

A filter that is safe under `paired` and unsafe under `solitary` is **redundant
but load-bearing**, which is a distinct and reportable outcome from either
"essential" or "inert".

## 4. Violation class per filter — what removal must let through

| filter | violation admitted if removal changes the answer |
|---|---|
| F1 / R1 | cross-permission leak: a claim the asker may not see becomes the answer |
| F2 / R2 | a claim outside its valid interval answers an as-of question |
| F3 / R3 | wrong-scope answer: a Customer B claim answers a Customer A question |
| F4 / R4 | an explicitly excluded or overridden claim is used |
| R5 | a lower-authority claim outranks a higher-authority one |
| R6 | a less specific claim beats a more specific one at equal authority |
| R7 | a withdrawn/superseded source beats an active one |
| R8 | a staler claim beats a newer one, all else equal |
| G1 | an unresolvable conflict is silently resolved instead of raised for review |

## 5. Classification rule — frozen before results

Each (filter, state) result is classified into exactly one of:

- **A — essential.** Removal admits the violation. The filter is the only thing
  refusing it.
- **B — redundant for the verdict.** Removal changes no answer *and* another
  named filter is shown to block the same violation. **The blocking filter must
  be identified, not assumed.** "Nothing changed" without naming the blocker is
  class **U**, below.
- **C — verdict-redundant, diagnostically load-bearing.** The answer is
  unchanged but the resolution's `status`, `reason` or `required_review` changes.
- **D — not claim-load-bearing.** No verdict change, no diagnostic change, and
  no claim element depends on it. This is the only class that licenses removing
  a limitation from the claim.
- **U — unresolved.** Behaviour changed in a way none of A-D describes, or a
  null with no identified redundant blocker. **U is reported as U.** It is not
  rounded to B.

## 6. Positive control, per filter

Every filter gets its own separating control: a state constructed so that the
filter *is* the only thing standing between the query and the violation, with
the expectation recorded before running. **If a filter's positive control does
not separate, that filter's null is uncitable** and it is reported as
`INSTRUMENT_DID_NOT_SEPARATE`, exactly as H1-I Amendment 1 required.

This is the lesson from H1-I attempt 2 applied in advance rather than after.

## 7. Negative / no-op control

A control state in which no filter should change anything, run against every
ablation. Any ablation that changes this state's answer is **manipulating
something other than the filter it claims to manipulate**, and that ablation's
result is void.

## 8. Narrowing rule — binding

- A filter classified **D** across every state means the corresponding claim
  limitation is **not supported and must be narrowed or dropped**.
- A filter classified **B** everywhere means the claim may not recite it as
  independently necessary; permitted wording must say the guarantee is joint.
- Only **A** and **C** support reciting a filter as load-bearing, and **C** only
  for diagnosis, never for the verdict.

Accepting these in advance is what makes this an experiment. Rewriting a class
after seeing which claim it weakens is prohibited.

## 9. Forbidden wording

- "every governance filter is necessary" — unless every filter classifies A.
- "the authority ordering was validated" — ranking-element ablations test
  ordering effects, not calibration of the ranks themselves.
- any citation of a null without its positive control.
- describing a class-B filter as redundant *code*: redundancy for a verdict on a
  frozen case set is not evidence that the filter can be deleted, and defence in
  depth is a design property this experiment does not evaluate.
- presenting `CONFLICTED` as a failure. Refusing to answer is the designed
  behaviour and counts as the guard working.

## 10. Stop rule

One execution over the frozen state set. No state is added, removed or edited
after results are seen. If a positive control fails to separate, that filter's
harness is corrected and the correction is recorded as a superseded attempt —
the protocol is not amended to fit. Deterministic, CPU-local, no network, no
GPU, $0.
