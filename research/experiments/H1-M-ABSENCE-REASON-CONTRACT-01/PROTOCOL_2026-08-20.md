# H1-M — absence-reason contract audit

**Purpose.** Close Pass K finding `A2/1 = ELEMENT_IMPLEMENTED_ONLY` by binding
claim A2's recital to an observable produced by the live implementation.

**Evidence class.** `CONTROLLED_IMPLEMENTATION_CONTRACT_AUDIT`. No external
corpus, no GPU, no new mechanism, no benchmark. `external_gpu_cost_usd = 0.0`.

**This is not a real-data measurement and must not be promoted to one.** It says
what the implementation records when a signal has no value. It says nothing about
how often that happens in real documents, and nothing about whether
`MissingReason` enumerates every way a signal can be absent.

---

## 1. What the claim recites

> the abstention decision is recorded with the identities of the signals that
> were present, the signals that had no value, and, for a signal represented as
> absent by the decision, an enumerated absence reason distinguished by the
> implementation, such that an abstention is distinguishable from a failure to
> evaluate

Four observables follow, and each is a named contract test:

1. present signal identities are recorded;
2. absent signal identities are recorded;
3. every absent signal carries a reason drawn from the implementation's
   enumeration (`akc_cir.identity.MissingReason`);
4. the record distinguishes an absence-caused abstention from an abstention
   reached after a complete evaluation, and from an evaluation that produced no
   decision at all.

## 2. Subject under audit

Live, unmodified:

- `packages/cir-python/src/akc_cir/identity.py` — `MissingReason`,
  `LogicalIdentityDecision.missing`, `LogicalIdentityResolver.decide_pair`.

No source file is edited by this experiment. The only new artifact is the
contract test module.

## 3. Controls

**Positive control.** A pair on which every signal has an input must produce a
decision whose `missing` map is empty and whose `signals` map covers all seven
weighted signals. If absence were reported unconditionally, the recital would be
vacuous.

**Negative controls (break controls).** Two constructed defects must be rejected
by the same predicates the passing tests rely on:

- a signal recorded as absent *and* given a numeric score (the zero-fill defect
  §N4.4 forbids) must fail the disjointness predicate;
- a free-text absence reason must fail the enumeration predicate.

A guard that cannot fail is not a guard, so both break controls are part of the
required test set and their absence fails the audit.

## 4. Decision rule

PASS only if every required contract test is present by name in the pinned test
module **and** pytest exits zero over it. Any drift in a pinned file's bytes
between freeze and run aborts the audit rather than re-freezing.

## 5. Boundaries that travel with the result

- Controlled implementation evidence. Not a real-data measurement.
- No completeness claim over the absence taxonomy. `MissingReason` enumerates
  the reasons this implementation distinguishes; nothing here establishes that
  the enumeration is exhaustive, and the claim is drafted so it does not need to
  be.
- "Distinguishable from a failure to evaluate" is established in the narrow
  sense the tests exercise: an abstention carrying an absence record is
  distinguishable from an abstention reached after a complete evaluation, and a
  refused evaluation produces no decision object to be mistaken for either. It
  is **not** a crash-safety result.
