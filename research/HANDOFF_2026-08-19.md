## 1. Working rules that were learned the hard way

These came from real failures in this run. Violating them reproduces the failure.

- **Never let a milestone become a claim.** Split claims until each one names
  exactly one thing that was measured. `B-SAFETY` had to be split three times.
- **A contained failure is a failure.** If the planner leaves an artifact stale
  and the gate blocks the run, equivalence *failed* and safety *held*. Never
  score the first as a pass because the second worked.
- **Freeze acceptance criteria before looking.** And make upper bounds binding —
  a ceiling is a failure, which is how the W6 v1 question set died.
- **Never widen a threshold after seeing a result.** Add the new statistic as a
  *measurement*, and freeze it as a criterion only in the next protocol.
- **A zero is worthless until something makes it non-zero.** Every safety claim
  here carries a falsification arm that produces the failure on purpose.
- **Trace root causes; never assume "generator artifact".** Two harness bugs and
  one real Protected Core gap were separated only by dumping the actual diff.
- **When a result contradicts an earlier conclusion, correct it immediately and
  in writing**, including in source docstrings. Do not soften the earlier text.
- **Superseded receipts are retained, never edited or deleted.** A superseding
  receipt pins the old one's sha256.
- **Development data is not confirmatory.** A suite that found a bug cannot
  confirm the fix for that bug.
