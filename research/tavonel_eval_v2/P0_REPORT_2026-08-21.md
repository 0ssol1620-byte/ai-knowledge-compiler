## C. Oracle independence

The prior in-repo equivalence work computes its "independent full rebuild" with
the same function, in the same process, from the same parser as the selective
path (`run_public_real_revision_holdout_v3.py`, `run_pair` → `artifact_hashes`
for both sides). That is same-code recomputation, not independence. v2 does not
inherit it.

| separated | how | observed |
|---|---|---|
| executable | `oracle/independent_full_build.py` is a standalone re-implementation of the artifact spec | sha256 recorded |
| code | AST scan of every import | `['__future__','argparse','hashlib','json','os','pathlib','sys','time','typing']` — non-stdlib imports: **none** |
| process | `subprocess`, pids compared per pair | distinct on **30/30** pairs |
| reachability | child runs `python -I -S` | `cir_python_on_path: false`, non-stdlib modules loaded: **none**, on 30/30 |
| runtime | `sys.meta_path` guard refusing `akc_cir` | probed each run; `akc_cir` import **blocked: true** |
| inputs | oracle argv carries only the AFTER canonical document | no dirty set, no plan, no prior state, no cache |
| outputs | `artifacts/development/{selective,oracle,comparison}` | disjoint: true |
| comparator | `comparator/compare_states.py` | imports neither engine; own guard |
| determinism | oracle run twice on one input | identical `state_hash` |

`-I` alone was **not** sufficient: the first run showed
`cir_python_on_path: true` because this repository installs `akc_cir` into
site-packages in editable mode, which `-I` does not drop. That run is preserved
as `…-run1-superseded.json`. Adding `-S` makes the selective implementation
unreachable rather than merely unimported.

The shared surface is exactly two things, both permitted by §8.4: the canonical
document written to disk once, ahead of both builds, and the artifact
specification, which each side implements separately.

**The two timings are not comparable and neither is an efficiency result.**
The selective implementation computes the full AFTER state in order to have
values to write for the artifacts it does decide to rebuild, so its 124 ms
includes a complete rebuild plus the diff, the one-to-one identity assignment
and the graph traversal. It is an upper bound on a correctness harness, not a
measurement of selective work. No speedup, slowdown or Pareto point may be read
off this table. The structural counts -- rebuilt fraction, work avoided,
unnecessary rebuilds -- are valid, because they count decisions rather than
seconds. Efficiency is RQ6's subject and needs an implementation that actually
skips the work it says it skips.

## E. Findings

### E1 — the previous full-rebuild oracle was not independent

Recorded in section C. It does not make the 28-pair Wikipedia numbers wrong; it
means the word *independent* in that result describes a recomputation, and only
the v2 construction supports the stronger reading.

### E2 — a case-only edit escapes invalidation (`INC-V2-002`, open)

`rust-lang/book`, `src/ch04-01-what-is-ownership.md`: two sections whose only
change is `w`→`W` (and `t`→`T`). `normalize_text_for_identity` casefolds, so the
differ saw no change; artifact spec v1 stores raw text, so the full rebuild
produced different bytes. Two artifacts carried forward stale.

The general form: *where an artifact payload is finer-grained than the
normalisation its change detector compares under, the difference between them
is a silent stale window.* Same shape as the published structure-only defect, a
different axis.

Not repaired. The spec was not changed to normalise the payload, the parser was
not changed to fold case, and the protocol was not amended — any of those would
have converted a measured failure into a passing gate.

**Bearing on the 28-pair result:** that adapter builds section artifacts from
`normalize_text_for_identity(...)`, so detector and payload share one
normalisation and this failure mode could not have arisen there. It is a
boundary on the claim, not a contradiction of it.

### E3 — sealed evidence drift (`INC-V2-001`, blocked)

4 bindings and 2 receipt self-hashes no longer verify, with no superseding
receipt. Line endings and HEAD bytes were both ruled out. Three verifier false
positives were found and fixed first (missing bindings 173→0, self-hash failures
13→2); what remains survived those fixes. Nothing was modified or re-sealed.

### E4 — unresolved identity is common on real prose revisions

8 of 26 natural pairs carry at least one unresolved identity. The fail-closed
path handled every one, but the rate matters for P2 and for how much of the
rebuilt fraction is precaution rather than necessity.

### E5 — 36% of rebuilds were unnecessary

56 of 155 rebuilt artifacts had bytes identical to their prior value. Correct
but wasteful, and it sets the baseline the efficiency work in RQ6 has to beat.

### E6 — SEC yields few admissible pairs at this parse quality

10 SEC pairs fetched, 4 admitted; 8-K amendments are too short to clear a
3-unit floor. The family works but needs either a better structural parser for
EDGAR HTML or a bias toward longer forms before it can carry its share of a
500-pair corpus.
