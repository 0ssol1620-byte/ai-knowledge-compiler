# Monitoring Contract

The rules cover security, job completion, queue age, provider availability,
cold start, DLQ, unsupported claims, duplicate billing, cost, deletion, model
revision drift, and the v6 parallel shard/attempt/validation/continuity
lifecycle. Initial numeric thresholds are operational defaults, not sales SLOs;
owners must version them from route-specific baseline data.

The API emits privacy-safe HTTP, scanner, audit, credit, job, page, provider,
and fixed-cardinality product-analytics contract series. The webhook scheduler
emits dead-letter and deletion-backlog gauges.
The dispatch worker emits global queue gauges and the compile-domain counters
generated by committed jobs. `service-monitors.yaml` scrapes all three
surfaces. Gauge alerts use `max`-style aggregation because every HA replica
observes the same durable global state.

The v6 parallel series deliberately have only bounded status, validation-level,
health-projection, recovery-level, billing-class, provider, and measurement
labels. Tenant, document, job, shard, attempt, worker, model-revision, artifact,
and content values are never label inputs. Provider queue delay, execution time,
GPU time, and USD cost must come from validated provider receipts; cost is not
inferred from credits. Lifecycle counters must be scheduled after the durable
database transaction commits so rollbacks and idempotent replays cannot create
phantom outcomes.

`AKCRequiredTelemetryContractMissing` and `AKCMetricsScrapeMissing` remain
fail-closed: absence is an incident, not a reason to waive the release gate.
Scanner and provider availability are emitted only after a real health result;
they are not initialized optimistically.

FastAPI spans contain method, framework route template, status, service, and
environment only. Concrete paths, query strings, request/response bodies,
headers, tenant IDs, object IDs, filenames, and generated content are excluded.
The collector repeats those deletions as defense in depth. OTLP export is off
by default locally and is mandatory, with an explicit credential-free
collector origin, in the production API configuration.

Telemetry permits identifiers, states, hashes, durations, counts, quality
findings, and costs. It forbids document text/images, generated content,
presigned URLs, credentials, and direct personal identifiers.

Product analytics remains tenant-local. Prometheus sees only bounded snapshot
and event outcome labels, never tenant/user/object IDs or the selected window.
Metric/cohort definitions, opt-out behavior, and incident response are in
`docs/runbooks/product-analytics.md`.

Before deployment:

- replace the collector's sampled `debug` trace exporter with an approved
  authenticated backend; the checked-in exporter is local diagnostics only;
- install the Prometheus Operator CRDs and apply `service-monitors.yaml`;
- preserve the monitoring-only NetworkPolicies for all scrape targets;
- connect Alertmanager routes and environment-specific budget thresholds;
- make runbook links absolute;
- define route/plan p50/p95 objectives and error-budget windows;
- run the privacy regression tests that reject concrete IDs in labels/spans;
- test alert delivery in staging.
