## ③ 이 설계도 원안과 다른 점 — 명시

§12.2 원안은 "**실제 컴파일이 시작되고** 좌측이 사용자 문서로 교체된다"이다.
그대로 하려면 **익명 ingest 계약**이 필요하고, §24.4 는 "백엔드 API 계약
변경이 필요함"을 중단 조건으로 둔다.

확인한 사실:

```
API 의 모든 업로드 경로가 tenant-scoped   uploads/initiate → EditorDep
데이터 모델이 테넌트 단위 + RLS           postgres-rls-and-role-boundaries 잡이 검증
마케팅 표면에는 세션이 없다
```

따라서 이번 웨이브의 ③ 은 **업로드하지 않는다.** 대신 브라우저가 확정할 수
있는 것만 계산해 보여주고 실제 인증 흐름으로 인계한다.

```
계산하는 것    파일명 · 크기 · MIME · SHA-256
              SHA-256 은 인증 업로드 경로가 무결성 검사로 보내는 것과 같은 값이다
              (upload-client.ts 의 browserSha256 재사용)
모르는 것     페이지 수 · 구조 · 근거 커버리지
              → "컴파일 중에 측정된다"고 쓴다. 추정하지 않는다 (§25.7)
```

**"이 기기를 떠나지 않았습니다"는 문자 그대로 사실이다.** 네트워크 요청이
없다. 제품의 프라이버시 논지를 문장으로 주장하는 대신 첫 상호작용에서
실증한다.

검증 — 화면에 표시된 다이제스트가 `node:crypto` 의 SHA-256 과 정확히 일치함을
확인했다. 크기 193 B 도 실제 바이트 수다.

```
node crypto : cef3b030a93763cb836367821d6d398a276b6844b783f9e1b8f8bfca4d22e637
화면        : cef3b030a9…ca4d22e637
```

## 다음 웨이브에서 닫는다

익명 preflight 계약을 별도 PR 로 연다. 보안 민감 변경이라 CSS 와 같은 PR 에서
리뷰되면 안 된다. 설계 방향:

```
시스템 데모 테넌트     테넌트 단위 RLS 를 우회하지 않고 재사용한다
preflight 전용         GPU 컴파일은 열지 않는다 — 비용 노출
짧은 TTL               deletions.py 의 보존 경로 사용
남용 한도              _consume_rate_control(control="upload") + CAPTCHA 에스컬레이션
                      IP 가명화 · 메트릭이 이미 있다
절차                   CONTRIBUTING.md — ADR → 스키마 → 클라이언트 타입 → 회귀 테스트
```

## 이번 웨이브에 포함되지 않은 것

- **§12.2 모션 5구간** — 액자 페이드인부터 VERIFIED 배지까지. 시퀀스는
  스크롤 리빌과 함께 다뤄야 해서 Navigation 시안 뒤로 미룬다.
- **Navigation** — §24.1 상 시안 승인 전 구현 금지. 아직 시안이 없다.
- **홈 라우트 교체** — 현행 `/` 는 레거시 마케팅 페이지다. 이 Hero 를 그
  자리에 넣는 것은 Navigation 이 정해진 뒤다.
