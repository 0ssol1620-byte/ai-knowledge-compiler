자동화 브라우저에서 첫 Compiled World 생성 이벤트를 다시 실행했으며, 생성 후 프로젝트 상태와 수집 입력의 변화를 계속 확인한다.

첫 Compiled World가 실제로 생성돼 `Add a source` 상태로 전환됐다. 현행 파일 입력은 단일 파일만 허용하고 PDF·PNG·JPEG·WebP·텍스트만 받을 수 있으므로, 다음 단계에서 다중 파일·ZIP·폴더 드래그앤드롭 계약으로 확장한다.

다중 파일 수집 확장 뒤 첫 입력은 PDF·이미지·텍스트·CSV·ZIP을 `multiple`로 받고, 폴더 입력도 별도의 `multiple` 수집 경로를 제공하는 것을 인증된 브라우저에서 확인했다.

인증된 First Compiled World에 비민감 테스트 원본을 실제 업로드했고, 수집 UI가 `Preserving 0 / 1` 상태로 전환되는 것을 확인했다. 서버 저장 완료 및 중복·컴파일 결과는 다음 상태 갱신에서 확인한다.

저장 완료 뒤 원본 1개와 중복 0개가 Evidence Engine에 반영됐고, `Compile this world` 실행을 시작했다. 서버 단계 전환 및 검토 가능한 제안 구조가 표시되는지 다음 갱신에서 검증한다.

자동화 브라우저에서 컴파일 버튼의 이벤트를 다시 실행했다. 현재 UI가 다음 단계로 갱신되는지와 서버 실행 상태를 이어서 점검한다.

ZIP 수집 검증을 위해 인증된 브라우저의 첫 수집 입력을 확인했으며, `.zip`을 포함한 다중 파일 선택 계약이 활성화된 상태다.

안전한 테스트 ZIP을 실제 고객 프로젝트에 업로드해 내부 원본 2개가 해제·저장됐고, 기존 원본과 바이트가 같은 항목 1개가 `COPY`로 표시됐다. Evidence Engine은 총 4개 원본과 1개 중복을 표시해 ZIP 해제·다중 수집·해시 기반 중복 탐지 경로를 검증했다.

다시 실행한 서버 컴파일은 `context-note.txt`를 대표 원본으로 선택해 제안 디렉터리와 검토 큐를 생성했고, 중복 1개를 보존한 copy relationship을 결과에 명시했다. 로그인 → 수집 → ZIP 해제 → 중복 탐지 → 컴파일 → 검토 가능한 구조 제안의 실제 흐름을 끝까지 확인했다.

SEC 공개 데모는 1280px 및 390px에서 원문면·컴파일 코어·제안 컨텍스트·4단계 컨트롤이 일관된 Compiled World Atlas 체계로 표시되는 것을 확인했다. 공개 fixture라는 점과 자동 결론이 아닌 설명용 인터랙션이라는 점도 화면에 명시했다.

코드 분할 뒤 1280px에서 공개 flagship과 SEC 공개 데모가 모두 정상 렌더링됐다. `/world`는 로그인 전 상태로 인해 애플리케이션 본문 대신 양피지 바탕의 인증 경로를 반환했으며, 실제 작업공간 본문은 로그인 세션에서 확인해야 한다.
